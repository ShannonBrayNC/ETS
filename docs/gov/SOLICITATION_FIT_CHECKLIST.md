# ETS Solicitation Fit Checklist

Use this checklist before responding to a government opportunity.

## Fast triage

- [ ] Opportunity is about evidence integrity, provenance, auditability, AI governance, cyber, automation controls, DevSecOps, incident evidence, emergency telemetry, or records verification.
- [ ] Opportunity does not require ETS to be an official system of record without partner support.
- [ ] Opportunity does not require certified voting, tabulation, voter-registration, ballot-marking, ballot-counting, or election-correctness software.
- [ ] Opportunity allows prototype, pilot, proof-of-concept, research, innovation, SaaS, software, or technical services response.
- [ ] Opportunity permits small business, individual founder, startup, or prime/subcontractor participation.

## Technical fit

- [ ] EvidenceEvent lifecycle maps to the solicitation problem.
- [ ] Canonical hashing / proof material maps to the requirement.
- [ ] Verification certificates map to audit/compliance/reporting needs.
- [ ] Policy-gated routing maps to workflow action, human review, or escalation needs.
- [ ] Audit replay maps to reproducibility or oversight needs.
- [ ] Existing prototype or demo can be shown without exposing private IP records.

## Public-sector risk boundary

- [ ] Proposal states ETS verifies submitted-event metadata and proof material, not real-world truth.
- [ ] Proposal states ETS does not prove legal sufficiency.
- [ ] Proposal states ETS does not prove election correctness.
- [ ] Proposal states ETS is not voting, tabulation, voter-registration, ballot-marking, ballot-counting, or vote-of-record software.
- [ ] Proposal avoids using confidential USPTO application details.

## Business-readiness fit

- [ ] Entity identity is clear: individual, EchoMedia.AI LLC, or partner prime.
- [ ] SAM.gov path is ready or partner prime can carry contracting access.
- [ ] Capability statement is updated.
- [ ] Demo script is ready.
- [ ] Price/pilot scope is reasonable.
- [ ] Security posture and data-handling boundaries are documented.

## Recommended response model

### Lead response

Use when ETS is directly aligned, non-regulated, and demo-ready.

### Partner/subcontractor response

Use when the buyer requires existing contract vehicles, FedRAMP, ATO, past performance, cleared staffing, agency incumbency, or large-delivery capacity.

### No-bid

Use when the opportunity requires certified voting systems, legal system-of-record authority, full production authorization, or regulatory credentials ETS does not yet hold.
