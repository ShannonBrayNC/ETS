### Civic and election-adjacent caution lane

Use carefully and only with boundary language.

- election audit evidence
- civic evidence
- election records audit
- election-adjacent evidence
- public trust records
- election cybersecurity evidence

Do not market ETS as voting, tabulation, voter registration, ballot marking, ballot counting, election correctness, or vote-of-record software.

## Buyer problem statements

### Problem: AI decisions need audit trails

ETS fit:

- Capture evidence events before AI outputs trigger action
- Generate proof material
- Certify verification status
- Route to human review when policy requires

### Problem: cyber release pipelines need tamper-evident evidence

ETS fit:

- Hash submitted evidence
- Append evidence events
- Verify inclusion and tree-head progression
- Gate release workflows on verified proof material

### Problem: emergency and sensor systems need reproducible evidence handling

ETS fit:

- Ingest telemetry/event records
- Generate proof and replayable audit records
- Route sensitive events for human review or escalation

### Problem: agencies need boundaries around civic evidence claims

ETS fit:

- Verification certificates include explicit non-claim labels
- Public output avoids overclaiming legal truth or election correctness
- Audit replay supports evidence review without becoming the system of record

## Disqualifier phrases

If a solicitation requires the following as core scope, ETS should not lead unless partnered with a certified provider:

- official voting system
- tabulation system
- voter registration system
- ballot marking device
- ballot counting system
- legally authoritative chain of custody
- certified system of record
